# Tagged outcome values

Owner: `story:tagged-union-outcomes`; requirement R-128. Outcome definition and record
profile 3 extend [profile 2](kernel-typed-outcomes-v2.md). Earlier profiles retain
their admitted vocabulary, serialized bytes and replay semantics. This is a kernel
prerequisite for ESS lowering, not a claim that a service uses that lowerer.

## Selected payloads

```json
{"type":"union","required":true,"union":{
  "tag":"kind","content":"value","variants":{
    "input":{"type":"object","properties":{"name":{"type":"string","required":true}}},
    "constant":{"type":"object","properties":{"value":{"type":"string","required":true}}}
  }
}}
```

The value is a closed object containing exactly the declared tag and content
properties. The tag must be a string naming a declared alternative. The content
must satisfy that alternative's complete field definition. No tag default,
first-matching-shape selection, unknown-tag fallback or implicit payload exists.
Tag and content names must be nonblank and distinct; alternatives must be nonempty
and have nonblank names. The wire binding chooses both property names explicitly.
For example, an ESS tag called `value` uses its established separate content name;
the kernel does not infer a layout from an ESS-specific convention.

Every alternative is recursively validated at registration, including dormant
alternatives and defaults. An envelope can carry arrays, maps, nullable values or
further unions. Runtime validation selects one alternative and accumulates errors
within that payload together with undeclared envelope properties. Explicit null
union metadata is refused, including under older profiles, rather than interpreted
as an omitted declaration. An invalid tag
prevents checking a payload whose type cannot be selected; it does not hide a
missing payload or extra envelope property.

Defaults recurse into a supplied selected payload. They never create a missing
payload property or replace explicit null. `required` on the containing union field
controls its omission; tag and payload are always required once an envelope exists.
As with array element definitions, a payload definition's root `required`/`default`
does not create a missing container slot.

Arguments, entity state, materialized events and business errors all use the same
validator. An invalid payload cannot yield a successful record. JSON Schema
projection uses one closed object branch per tag under `oneOf`, with both
properties required. New schema metadata is omitted from serialized old fields.

## References and replay

A union's tag is a known scalar address. Descending below that tag or naming an
undeclared envelope property is a registration error. A payload path must exist in
every alternative. It can be a typed quantifier target only if all alternatives
give it the same complete field definition. Thus a payload that is an array for
one tag and a string for another cannot be quantified by asserting a different tag
elsewhere in the predicate; there is no branch-narrowing type system here.

This rule preserves the existing template and lexical-binding scopes. It does not
add a dynamic JSON selector or permit a dormant branch to read undeclared data.
Union-contained typed relation targets are traversed by the schema walker and
reference diagrams too;
cross-instance referential integrity still belongs to explicit storage/bindings.

The existing pure outcome implementation selects commands, applies changes,
validates payloads and constructs complete `entity-outcome-record/3` records.
Replay redecides the recorded invocation and compares every result and event.
Changing a tag, payload or format is not permission to reinterpret history.
Legacy registration and outcome profiles 1 and 2 refuse `union` at every depth.
Older published readers reject profile 3 and its union metadata explicitly.

## Evidence and remaining work

Tests exercise closed tag-selected payloads, accumulating errors, selected nested
defaults, null versus absence, dormant-invalid alternatives, checked tag/payload
references, typed events/errors, complete replay and old profile admission.
The independent retained probe uses the actual `connectors.declarations.Parameter`
schema generated by ESS `e14d75fb8c0b9f845dfead6a4fa5309f14bb7c63` from Connectors
`dd3df88c1ed62e7c4d8ee740426ebd80674754fb`. Its manually expected vectors are upstream
of ER. Removing selected-payload validation must make that probe fail.
Published ER `421e291b7e07cf6e381488b9b60763ed86ac4fc9` is the independent reader
and canonical-byte compatibility baseline. The AEP evidence records exact runs.

No ESS, IO or provider dependency is added to the kernel. Scalar codecs, nominal
type/nested invariants, exact identity and multi-entity binding, ESS-to-ER lowering,
service-engine delegation and complete application adoption remain separate work.
The operator excludes the full gate; affected checks do not claim a release.
