## Context

ESS evolution migration step 3 requires faithful lowering of ResolvedBody::Union. Connectors declares connectors.declarations.Parameter in ess/domains/declarations.yaml:22-28, whose kind selects input/binding NamedParameter or constant ConstantParameter. ESS uses an adjacent tag and content representation; ER profile 2 cannot validate the selected payload. Generic JSON or a flattened object would admit invalid combinations.

## Acceptance

An explicit new outcome profile validates closed, tag-selected typed payloads recursively across arguments, entity fields, events and business errors, preserves defaults and replay, refuses malformed dormant variants, and agrees with independently generated ESS schemas for the existing Connectors Parameter union while legacy and profile-1/profile-2 bytes and reader boundaries remain unchanged.

## Design

Add a concrete tagged union field definition with explicit distinct tag/content names and a closed map of typed payload alternatives. Only outcome profile 3 admits it; old profiles reject it. Do not add ESS or IO dependencies to the kernel. Validate every variant at registration and only the selected value at runtime; unknown/missing/non-string tags, missing payload and extra envelope fields refuse. Defaults recurse only into the selected supplied payload. Union tag references and payload paths shared by every alternative retain schema checking; no dynamic branch-specific reference bypass.

This is a required kernel prerequisite, not a substitute for the full ess-entity-runtime target, scalar codecs, nested type invariants, identity/multi-entity binding or service-engine delegation. New source types mirror existing ESS declared unions; no new application entity is invented.

## Scope

Cited: crates/entity-core/src/{definition,validation,outcome,registry}.rs own the types, admission and execution profiles; crates/entity-surface/src/lib.rs projects field schemas; core and surface tests prove behavior; docs/requirements.md, CHANGELOG.md and docs/design/kernel-tagged-outcomes-v3.md record the contract. Independent retained probe compares published profile-2 readers and actual ESS-generated Connectors schemas.
